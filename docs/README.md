# OctoAcme Project Management Docs

This folder contains the core project management guidance for OctoAcme. Use this page as the entry point for the documentation set and as a quick orientation for the lifecycle, roles, and recurring operating rhythms used by the team.

## Project Management Process Overview

OctoAcme uses a customer-first, iterative project lifecycle with clear ownership and evidence-based decisions. Work begins with initiation to confirm the problem, stakeholders, success measures, timeline, risks, and resources. Approved work then moves into planning, where the team creates a prioritized, estimated backlog, defines acceptance criteria and the Definition of Done, and identifies dependencies.

During execution, the team works in small increments using the project board, pull requests, automated quality checks, testing, regular status reviews, and structured blocker escalation. Risks and stakeholder communications are managed continuously through a shared risk register and regular updates. Releases require completed acceptance criteria, passing CI and security checks, release notes, rollback planning, staging smoke tests, and post-deployment verification. After each sprint, release, milestone, or incident, the team holds a retrospective and tracks a small set of measurable improvement actions.

## How to Use This Set

- Start with the overview and initiation guide when a new idea is being considered.
- Move to planning once the initiative is approved.
- Use execution and tracking during delivery to manage backlog flow, quality, and blockers.
- Maintain risk, communication, and release artifacts throughout a project.
- Close each milestone with a retrospective and incorporate the resulting improvements into future work.

## Related Practice

These docs are intended to help teams standardize project management practices, improve consistency across workstreams, and reduce single-person dependency risk by documenting how OctoAcme operates.
